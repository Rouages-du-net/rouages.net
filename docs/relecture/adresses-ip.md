## 1. Faits à vérifier

- [ ] **F1** · chapô, 🟢 : une adresse IP est un nombre de 32 bits en IPv4, de 128 bits en IPv6. Source : [8] RFC 791 https://www.rfc-editor.org/rfc/rfc791 ; [15] RFC 4291 https://www.rfc-editor.org/rfc/rfc4291. → Vérifié (RFC 791, RFC 4291) : rien à changer ; le 🔴 de l'étape IPv4 précise désormais qu'une adresse désigne une interface (voir S1).
- [ ] **F2** · étape « IPv4, quatre octets », 🟢 : quatre nombres de 0 à 255, chacun sur un octet de 8 bits ; 4 × 8 = 32 bits (calcul vérifié). Source : [8] RFC 791 https://www.rfc-editor.org/rfc/rfc791.
- [ ] **F3** · étape « IPv4 », 🟡 : 2³² adresses, « environ 4,3 milliards » (4 294 967 296, calcul vérifié). Source : [8] RFC 791 (32 bits) https://www.rfc-editor.org/rfc/rfc791 ; le nombre est un calcul.
- [ ] **F4** · étape « IPv4 », 🟡 : c'est « moins que d'humains sur Terre, et bien moins que d'appareils connectés ». Source : aucune trouvée dans le dossier. → Corrigé le 28/11/2026 : « à peine plus d'une adresse pour deux humains : nous étions 8,2 milliards en 2024, selon l'ONU » (ONU, *World Population Prospects 2024*, PDF lu, source [42]) ; le nombre d'appareils, non sourcé, est remplacé par « beaucoup d'entre nous ont plusieurs appareils connectés ».
- [ ] **F5** · étape « IPv4 », 🟡 : adresses privées 10.x.x.x, 172.16 à 172.31.x.x, 192.168.x.x (calcul vérifié : 172.16.0.0/12 va de 172.16.0.0 à 172.31.255.255), utilisées seulement à l'intérieur d'un réseau local. Source : [11] RFC 1918 https://www.rfc-editor.org/rfc/rfc1918. → Corrigé le 28/11/2026 : « à la maison derrière une box comme dans une entreprise » (RFC 1918, § 1, qui parle d'entreprises) ; voir S2.
- [ ] **F6** · étape « IPv4 », 🟡 : trois plages, dont 192.0.2.x, sont réservées aux exemples. Source : [12] RFC 5737 https://www.rfc-editor.org/rfc/rfc5737.
- [ ] **F7** · étape « IPv4 », 🔴 : la RFC 1918 définit les plages privées ; une box les traduit en une adresse publique (NAT). Source : [11] RFC 1918 https://www.rfc-editor.org/rfc/rfc1918 pour les plages ; NAT : aucune trouvée dans le dossier (voir V4). → Corrigé le 28/11/2026 : NAT sourcé par la RFC 3022 (P. Srisuresh, K. Egevang), ajoutée au bloc Sources et au dossier [34] ; NAT d'opérateur et 100.64.0.0/10 (RFC 6598) ajoutés.
- [ ] **F8** · étape « IPv4 », 🔴 : plages de documentation 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 (RFC 5737), qui ne désignent aucune vraie machine. Source : [12] RFC 5737 https://www.rfc-editor.org/rfc/rfc5737.
- [ ] **F9** · étape « IPv4 », histoire : IPv4 est décrit en septembre 1981 dans la RFC 791. Source : [8] RFC 791 https://www.rfc-editor.org/rfc/rfc791. → Vérifié (en-tête de la RFC 791, septembre 1981) : rien à changer ; auteur corrigé dans les sources (V7).
- [ ] **F10** · étape « IPv4 », histoire : le 3 février 2011, l'IANA, qui gère la réserve mondiale, distribue ses derniers blocs aux cinq registres régionaux. Source : [18] NRO, « Free Pool of IPv4 Address Space Depleted » https://www.nro.net/ipv4-free-pool-depleted/. → Corrigé le 28/11/2026 : précisé « un /8 (environ 16,8 millions d'adresses) à chacun des cinq registres » (NRO [18] : « final full /8 » ; AFRINIC [35] : « one /8 each, around 16.8 million »).
- [ ] **F11** · étape « IPv4 », histoire : le 25 novembre 2019, le RIPE NCC annonce avoir épuisé sa réserve. Source : [19] RIPE NCC, « The RIPE NCC has run out of IPv4 Addresses » https://www.ripe.net/publications/news/the-ripe-ncc-has-run-out-of-ipv4-addresses/. → Vérifié (RIPE NCC [19], page relue) : rien à changer ; région « Europe, Moyen-Orient, Asie centrale » sourcée par la page « About us » [37]. Encart complété par ARIN, LACNIC, APNIC et AFRINIC, « état au 28 novembre 2026 » (V2).
- [ ] **F12** · étape « IPv4 », mythe : les réserves libres des registres sont épuisées, mais les adresses déjà distribuées servent toujours, se revendent ou se partagent (une box partage une adresse publique). Source : [18] et [19] pour l'épuisement ; la revente n'est mentionnée que dans les « Points d'attention » du dossier, sans source (voir V2). → Corrigé le 28/11/2026 : voir V2 (récupération : RIPE NCC [19], LACNIC [38] ; transferts : ARIN [36], « IPv4 Transfer Market »).
- [ ] **F13** · étape « IPv6 », 🟢 : 128 bits, quatre fois plus qu'IPv4, écrits en 8 groupes de 4 chiffres hexadécimaux séparés par « : ». Source : [15] RFC 4291 https://www.rfc-editor.org/rfc/rfc4291. → Vérifié (RFC 4291) : rien à changer ; ajout au 🟡 : un groupe abrégé s'écrit avec 1 à 4 chiffres et vaut toujours 16 bits (S6).
- [ ] **F14** · étape « IPv6 », 🟡 : deux règles de raccourci (zéros en tête effacés, une seule suite de groupes nuls remplacée par « :: ») ; `2001:0db8:0000:0000:0000:0000:0000:0001` devient `2001:db8::1` (vérifié avec `ipaddress`). Source : [15] RFC 4291 https://www.rfc-editor.org/rfc/rfc4291 ; [17] RFC 5952 https://www.rfc-editor.org/rfc/rfc5952.
- [ ] **F15** · étape « IPv6 », 🟡 : 2¹²⁸ adresses, « environ 3,4 × 10³⁸ » (3,4028 × 10³⁸, calcul vérifié). Source : [15] RFC 4291 (128 bits) https://www.rfc-editor.org/rfc/rfc4291 ; le nombre est un calcul.
- [ ] **F16** · étape « IPv6 », 🔴 : selon la RFC 4291, la plupart des adresses ont un identifiant d'interface de 64 bits, donc un réseau local est en général un /64. Source : [15] RFC 4291 https://www.rfc-editor.org/rfc/rfc4291.
- [ ] **F17** · étape « IPv6 », 🔴 : la RFC 5952 fixe une écriture unique : zéros en tête supprimés, « :: » le plus long possible (le premier en cas d'égalité), jamais pour un seul groupe, minuscules. Source : [17] RFC 5952 https://www.rfc-editor.org/rfc/rfc5952.
- [ ] **F18** · étape « IPv6 », 🔴 : 2001:db8::/32 est réservé à la documentation (RFC 3849). Source : [13] RFC 3849 https://www.rfc-editor.org/rfc/rfc3849.
- [ ] **F19** · étape « IPv6 », mythe : un seul « :: » par adresse, sinon on ne saurait pas combien de groupes chacun remplace. Source : [15] RFC 4291 https://www.rfc-editor.org/rfc/rfc4291 (la règle est dans la RFC, mais le dossier ne la reprend pas explicitement). → Vérifié (RFC 4291, § 2.2 : « The "::" can only appear once in an address ») : rien à changer ; citation ajoutée au dossier.
- [ ] **F20** · étape « Le masque », 🟢 : un masque a trois écritures : /24, 255.255.255.0, 24 bits à 1 puis 8 bits à 0 (vérifié). Source : [9] RFC 950 https://www.rfc-editor.org/rfc/rfc950 ; [10] RFC 4632 https://www.rfc-editor.org/rfc/rfc4632.
- [ ] **F21** · étape « Le masque », 🟡 : les 1 sont toujours à gauche ; un octet de masque ne peut valoir que 0, 128, 192, 224, 240, 248, 252, 254 ou 255 (vérifié pour /0 à /32) ; /17 = 255.255.128.0 (vérifié). Source : [10] RFC 4632 https://www.rfc-editor.org/rfc/rfc4632 (contiguïté non citée explicitement dans le dossier ; voir V5). → Corrigé le 28/11/2026 : « Aujourd'hui, dans un masque… » (voir V5) ; contiguïté sourcée par RFC 1812 et RFC 4632 § 5.1 (« the mask must be left contiguous »).
- [ ] **F22** · étape « Le masque », 🟡 : l'adresse du réseau s'obtient par un ET logique entre l'adresse et le masque. Source : [9] RFC 950 https://www.rfc-editor.org/rfc/rfc950.
- [ ] **F23** · étape « Le masque », 🔴 : un /n compte 2³²⁻ⁿ adresses ; la première désigne le réseau, la dernière sert à la diffusion ; il reste 2³²⁻ⁿ − 2 machines. Source : « Points d'attention » du § 2 du dossier ; [9] RFC 950 https://www.rfc-editor.org/rfc/rfc950.
- [ ] **F24** · étape « Le masque », 🔴 : un /31 relie deux routeurs avec ses 2 adresses (RFC 3021), un /32 désigne une seule machine. Source : [14] RFC 3021 https://www.rfc-editor.org/rfc/rfc3021 ; /32 : « Points d'attention » du dossier.
- [ ] **F25** · étape « Le masque », histoire : en 1981, la RFC 791 découpait les adresses en classes A (réseau sur le premier octet), B (deux octets), C (trois octets). Source : [8] RFC 791 https://www.rfc-editor.org/rfc/rfc791. → Corrigé le 28/11/2026 : ajouté « La classe se lisait sur les premiers bits de l'adresse » (RFC 4632 § 2 : MSB 0, 10, 110) ; voir S9.
- [ ] **F26** · étape « Le masque », histoire : les masques de sous-réseau arrivent en août 1985 (RFC 950). Source : [9] RFC 950 https://www.rfc-editor.org/rfc/rfc950. → Corrigé le 28/11/2026 : « En octobre 1984, Jeffrey Mogul décrit les sous-réseaux (RFC 917), que des organisations pratiquaient déjà ; ils sont normalisés en août 1985 (RFC 950) » (voir S10).
- [ ] **F27** · étape « Le masque », histoire : en 1993, pour freiner l'épuisement des classes B, le CIDR permet toute longueur de préfixe, notée « /n » (RFC 1519, remplacée en 2006 par la RFC 4632). Source : [10] RFC 4632 https://www.rfc-editor.org/rfc/rfc4632 (la RFC 1519 n'a pas de source à elle dans le dossier, seulement sa date ; voir V6 et V8). → Corrigé le 28/11/2026 : RFC 1519 ouverte (V. Fuller, T. Li, J. Yu, K. Varadhan, septembre 1993) et ajoutée au bloc Sources et au dossier [26] ; motifs complétés (V6) ; la RFC 1519 n'emploie pas la notation « /n » (paires réseau, masque), d'où « On note aujourd'hui la longueur du préfixe « /n », comme dans la RFC 4632 ».
- [ ] **F28** · étape « Le masque », mythe : 255.0.255.0 n'est pas un masque, car ses 1 ne sont pas tous à gauche (binaire vérifié : 11111111.00000000.11111111.00000000). Source : [10] RFC 4632 https://www.rfc-editor.org/rfc/rfc4632 (implicite ; voir V5). → Corrigé le 28/11/2026 : « Plus aujourd'hui » (voir V5) ; la RFC 950 donne elle-même l'exemple d'un masque non contigu, 255.255.255.88.
- [ ] **F29** · étape « Le masque », mythe : une adresse en 192.168 n'est pas forcément un /24, c'est la box qui choisit le masque. Source : aucune trouvée dans le dossier. → Corrigé le 28/11/2026 : « c'est la configuration du réseau qui fixe le masque (à la maison, celle de ta box, qu'on peut changer) » ; formulation générale, sans source spécifique (voir S11).
- [ ] **F30** · bilan : les cinq points reprennent les étapes ; plages d'exemple 192.0.2.0/24 et 2001:db8::/32. Source : [12] RFC 5737 https://www.rfc-editor.org/rfc/rfc5737 ; [13] RFC 3849 https://www.rfc-editor.org/rfc/rfc3849.

## 3. Simplifications à valider

- [ ] **S1** · chapô, 🟢, et glossaire `adresse-ip` (« Numéro qui identifie une machine ») : en réalité, une adresse IP désigne une interface réseau. Une même machine peut en avoir plusieurs (IPv4 et IPv6, Wi-Fi et câble). → Corrigé le 28/11/2026 (page) : le 🔴 de l'étape IPv4 dit qu'une adresse désigne une interface réseau. → À trancher : la définition partagée `adresse-ip` du glossaire (« Numéro qui identifie une machine ») est laissée telle quelle, car elle sert à d'autres modules.
- [ ] **S2** · étape « IPv4 », 🟡, « ne servent qu'à l'intérieur d'un réseau local, derrière une box » : les plages privées servent aussi dans les entreprises et les centres de données. Chez les opérateurs, le NAT à grande échelle utilise une autre plage, 100.64.0.0/10 (RFC 6598). → Corrigé le 28/11/2026 : 🟡 « à la maison derrière une box comme dans une entreprise » ; 🔴 : NAT d'opérateur et 100.64.0.0/10 (RFC 6598).
